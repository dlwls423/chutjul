# 개인정보·보안·화면 점검

## 적용한 보호

- 모든 API 처리 함수에 공통 보호 적용: 변경 요청의 Origin/Referer/Fetch Metadata 검증, 실제 스트림 바이트 제한, JSON/multipart 형식 검사, API 응답 no-store, 내부 5xx/권한 오류 내용 숨김. 헤더가 없는 브라우저 변경 요청은 거부한다. 자동화 토큰은 지정된 두 관리 API에서 별도로 검증하며 쿠키와 함께 보내면 예외를 적용하지 않는다.
- 요청 본문 상한은 일반 API 512KiB, 업로드 32MiB이며 개별 파일은 30MiB이다. 본문 읽기 이후에만 크기를 확인하던 경로를 보완했다.
- 답변 기록은 승인된 개인 계정만 읽고 쓴다. 비식별 본문·요약·근거·검증 여부를 허용 목록으로 저장하고 신청번호·파일명·추가 메타데이터는 거부한다. 브라우저에서 먼저 비식별 처리하고 서버에서 다시 잔여 개인정보를 검사한다.
- 문서 수정·삭제 권한은 본문 처리 부서가 아닌 source_files.owning_department로 검사한다. 관리자도 승인 상태를 확인한다. 부서 조회 실패 시 임의 부서 변경을 허용하던 fallback을 제거했다.
- 공개 테스트의 자료 변경·계정 저장 경로를 막는다. 기존 검색과 메모리 작성 데모는 유지한다. 테스트 DB에는 합성 자료만 있어야 한다.
- 일반 검색은 POST 본문으로 전달해 URL·일반 접근 로그에 검색어를 남기지 않는다. 애플리케이션/프록시에서 본문 로깅을 켜면 여전히 노출될 수 있으므로 본문 로깅을 사용하지 않는다.
- 안내서·Excel·기타 원본은 PC 로컬 도우미에서 처리한 비식별 준비 자료로만 등록한다. 브라우저 PDF 경로는 마스킹된 민원 PDF만 허용하며 업로드 파일명은 원본 이름 대신 해시 기반 이름을 사용한다. 기존 원본 데이터는 자동 삭제하지 않았다.
- 로그아웃은 해당 기기의 Supabase 세션 갱신 토큰 폐기를 요청한다. 실패하면 성공으로 표시하지 않고 재시도한다. 이미 발급한 접근 JWT는 만료 전 유효할 수 있다. 인증 서버의 일시 장애 때문에 사용자 쿠키를 지우지 않는다.
- 신규 가입 비밀번호 최소 12자, 로그인·AI·소관 분석에 제한된 메모리 burst guard 적용. 이 제한은 worker 재시작/다중 인스턴스에 걸쳐 공유되지 않으므로 운영 WAF 제한을 대체하지 않는다.
- DB/파서 오류 원문을 처리 이력과 서버 로그에 남기는 경로를 줄였다. 기존 DB의 과거 오류 메시지는 별도 확인 대상이다.
- 보안 헤더와 CSP의 object/base/form/frame 경계를 추가했다. 이는 script-src nonce 기반의 완전한 CSP가 아니다. WebGPU/WASM/로컬 도우미의 연결을 유지하는 범위로 적용했다.
- 로컬 도우미는 비 ASCII 토큰을 비교 전에 거부하고, 시작 시 임시 파일 정리가 끝나야 요청을 받는다. 정리 실패 시 원문 결과를 반환하지 않는다.

## 화면과 개발 안정성

모바일·태블릿 폭에서 작성 도구와 입력 영역을 재배치하고, 긴 제목/본문의 줄바꿈, 탭 가로 스크롤, 44px 터치 영역, 입력 글자 크기, 키보드 포커스, safe-area 및 동적 화면 높이를 반영했다. 민원 탭은 방향키/Home/End로 이동한다. 비식별 저장 안내와 공개 테스트 안내를 분리했다.

Cloudflare의 전역 타입과 DOM 타입 충돌을 분리하고 실제 타입 오류를 수정했다. Excel 라이브러리 v9는 여러 시트 객체를 반환하므로 첫 시트 행을 읽는 readSheet API로 맞췄다.

## 검증 결과

- 개인정보 회귀 242/242, 탐색 결함 0/3 통과.
- 답변 형식, 로컬 문서/실제 합성 XLSX 첫 시트 파싱, 작성 탭/충돌/소유자, 전체 부서 집계, 보안 API/업로드/세션 회귀 통과.
- `tsc --noEmit` 및 Vinext 빌드 통과. 큰 번들/페이지 정적 분류 경고는 남아 있다.
- kordoc 도우미의 실제 HTTP→MCP→파서 9개 형식/경로 테스트, 잘못된 토큰/출처/확장자 및 임시 파일 정리 검사 통과.
- Next 16.3.8, React/React DOM/RSC 19.2.8, Vite 8.0.16 및 전이 의존성 수정 버전 적용. 루트 `pnpm audit --prod` 알려진 취약점 0건.
- 로컬 도우미 SDK 1.31.0 적용 후 도우미 전체 `pnpm audit` 알려진 취약점 0건.
- 루트 개발 의존성 전체 검사에는 [braces의 중첩 패턴 스택 고갈](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) high 1건이 남는다. `eslint-config-next` 및 Vinext 빌드용 glob 경로에 있으며 검사 시 수정 버전이 없었다. 신뢰하지 않는 프로젝트/패턴으로 빌드·lint를 실행하지 말고 수정 버전 배포 후 갱신해야 한다. 이 항목을 무시 목록에 넣거나 검사에서 숨기지 않았다.

의존성 점검은 실행 시점의 공개 advisory 기준이며, 아직 알려지지 않은 취약점을 증명하거나 배제하지 않는다.

## 배포 전에 필요한 확인

1. 기존 테스트 DB 상태를 확인하고 `202610120001_complaint_workspaces.sql` 이후 `202610130001_server_only_data_access.sql` 적용. 새 SQL은 관련 테이블 RLS 활성화 및 anon/authenticated/PUBLIC 권한 제거, 서버 역할만 허용한다. 실제 적용은 이 점검에서 수행하지 않았다.
2. 테스트/운영 Supabase 분리, Storage 비공개 및 정책, 서비스 키 노출 여부를 관리 콘솔에서 확인. 기존 원본·과거 로그·백업의 보유기간/파기 정책을 별도로 적용한다.
3. WAF의 지속적 요청 제한과 가입 남용 방지, 관리자 MFA, 이메일 소유 확인 절차를 확정한다. 현재 가입은 관리자 승인 방식이며 이메일 소유권을 인증하는 메일 흐름은 없다.
4. 실제 개인 계정 두 개와 서로 다른 부서로 조회·수정·삭제·자동 저장·복원·로그아웃 검증. 폐기된 세션과 만료 JWT의 동작도 검증한다.
5. 320/375/768/1024/1440px 및 200% 확대, 키보드/화면 읽기, iOS/Android 키보드 표시 상태에서 화면 검증. 로컬 서버와 앱 브라우저 사이 연결이 시간 초과되어 이번 환경에서는 시각 검증을 완료하지 못했다.
6. 실제 한국어 문서/OCR에 대한 누락·과잉 마스킹 평가. 이름·간접 식별·자유서술 민감정보는 정규식 검사만으로 완전하게 제거할 수 없다. 외부 AI 전송 전 담당자 확인 절차를 유지한다.

테스트 사이트 소유 권한과 소스 자격 증명 발급은 확인했으나, 자동 승인 검토가 자격 증명을 로컬 배포 도구의 stdin으로 전달하는 동작을 거부했다. 따라서 이번 수정은 배포되지 않았다. 제한을 우회하거나 인증정보를 파일에 저장하지 않았다.
