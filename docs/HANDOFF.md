# 첫줄 프로젝트 인수인계

최종 정리일: 2026-10-11  
기준 브랜치: `codex/search-wide-layout`

## 1. 프로젝트 목적

첫줄은 개인정보보호위원회 민원 업무를 지원하는 내부용 웹 서비스다. 과거 민원·답변, 안내서, Q&A 및 현행 법령을 부서별로 관리하고, 새 민원을 개인정보 보호형 처리 흐름으로 정리한 뒤 관련 근거를 검색하여 답변 초안을 생성한다.

핵심 원칙은 다음과 같다.

- 민원 원본 PDF와 마스킹 전 본문은 브라우저 밖으로 전송하지 않는다.
- 민원 데이터는 업무 조회용과 검색·AI 근거용의 2개 트랙으로 관리한다.
- 외부 AI에는 담당자가 확인한 비식별 요약과 재검사를 통과한 근거만 보낸다.
- 사용자는 자신의 부서 자료만 조회하고, 전체 부서 분석은 원문을 노출하지 않는 집계 신호로만 사용한다.
- AI 초안은 자동 확정하지 않으며 담당자가 근거와 문장을 최종 검토한다.

## 2. 주요 기능

### 새 민원 분석

- 질문 직접 입력 또는 국민신문고 형식 PDF 불러오기
- 브라우저에서 PDF 텍스트 추출, 개인정보 마스킹 및 비식별 요약
- 담당자가 전송 예정 내용을 편집하고 한 번 수락한 뒤 후속 절차 자동 수행
- 현재 부서의 유사 민원, Q&A, 안내서 및 현행 법령 검색
- 다른 부서 소관 가능성을 서버 내부 집계값으로 표시
- AI가 적합한 근거를 선택하여 정해진 개인정보위 답변 형식으로 초안 생성
- 근거를 사용자가 다시 선택하여 재작성
- 답변 방향성 프롬프트, 타이핑 효과, 복사 및 버전 저장

### 통합 검색

- 민원·법령·안내서·Q&A 통합 검색
- 민원 신청번호, 접수번호, 제목, 처리부서 및 본문 검색
- 안내서 검색 결과를 페이지별로 묶어 표시하고 원본 PDF 페이지 조회
- 민원 상세 메타데이터와 질의·답변 조회
- 넓은 화면에서는 자료 유형별 결과를 동시에 비교하고, 작은 화면에서는 반응형으로 재배치

### 데이터 관리

- PDF 및 Excel 다중 업로드
- 중복 파일 SHA-256 검사와 처리 상태 표시
- 민원 질의·답변 분리, 개인정보 마스킹, 검색 청크 생성 및 임베딩 저장
- 민원 PDF는 브라우저에서 마스킹된 이미지형 PDF만 Storage에 저장
- 민원 원문 대신 1차 마스킹본을 DB에 저장
- 업무 조회용 질의와 외부 AI용 질의 요약본을 2트랙으로 저장
- 외부 AI용 질의 요약본 사후 편집
- 안내서 전체 저장, 목차·페이지·법령 참조 중심 청크 생성
- 안내서 페이지 구조를 분석하여 Q&A 후보 자동 추출 및 별도 Q&A 자료로 조회
- Q&A 직접 등록
- 실패 사유 확인, 재처리 및 삭제

### 인증·권한·부서 관리

- 회원가입, 관리자 승인, 로그인 및 프로필 수정
- 관리자/사용자 역할 구분
- 사용자별 승인 이력 및 부서 변경 신청
- 부서 범위 데이터 접근
- 선택한 부서를 브라우저에 유지하고 수동 변경 전까지 사용
- 관리자가 권한 관리 화면에서 부서를 추가·삭제
- 테스트 사이트의 테스트부서는 인증 없이 사용할 수 있는 별도 모드 지원

### 법령 관리

- 국가법령정보 공동활용 API를 통한 법령·시행령·고시 동기화
- 현행 버전과 시행예정 버전을 구분하고 검색에는 현행 버전만 사용
- 이전 버전을 삭제하지 않고 본문 해시가 변경될 때 새 버전 추가
- GitHub Actions 및 보호된 `/api/legal/sync` API를 통한 주기적 동기화

## 4. 남은 작업과 알려진 문제

### 개인정보·보안

- 정규식과 소형 로컬 모델만으로 완전한 비식별을 보장할 수 없다. 실제 민원 표본으로 누락·과잉 마스킹 평가가 필요하다.
- `store: false`는 OpenAI Zero Data Retention을 의미하지 않는다. 실제 운영 전 기관 계약, DPA, ZDR 적용 가능 여부, 처리위탁 및 국외이전 검토가 필요하다.
- 업무 조회용 트랙과 AI용 트랙은 현재 논리적으로 구분되어 있다. 장기적으로 별도 스키마·전용 뷰·암호화 키로 권한까지 분리하는 것이 권장된다.
- 서비스 역할 키는 서버 전용이지만, 원문 조회·요약 편집·AI 전송에 대한 감사로그와 이상 접근 탐지는 추가 보강이 필요하다.
- 문서·청크·임베딩·답변 로그·Storage 파일·캐시를 함께 삭제하는 보유기간 및 파기 정책을 확정해야 한다.
- 전체 부서 소관 분석은 집계 결과만 반환하지만, 데이터가 매우 적은 부서에서 특정 사례가 추론되지 않도록 최소 문서 수 기준을 추가하는 것이 좋다.

### 업로드·파싱

- 이미지 전용 스캔 PDF는 브라우저 OCR을 제공하지 않는다. 텍스트 레이어가 없으면 OCR된 파일이나 직접 입력이 필요하다.
- 국민신문고 PDF 양식이 변경되면 질의·답변 분리 규칙을 업데이트해야 한다.
- 안내서 Q&A 자동 추출은 페이지 구조가 매우 다양한 문서에서 누락 또는 오탐이 발생할 수 있으므로 검수 UI와 평가셋 보강이 필요하다.
- 기존 데이터는 최신 마스킹 규칙 및 2트랙 요약 규칙으로 일괄 재감사할 필요가 있다.

### 검색·답변 품질

- 현재 검색은 키워드 점수와 저장된 청크를 중심으로 동작한다. pgvector 기반 의미 검색과 키워드 검색의 하이브리드 랭킹을 운영 데이터로 튜닝해야 한다.
- 부서 소관 확률은 통계적 확률이나 법적 판단이 아니라 상대적 일치 신호다. 평가 사례로 정확도와 표시 기준을 검증해야 한다.
- AI 초안의 법령 적용 및 사실관계 판단은 담당자 검토가 필수다.
- 법령 동기화 대상 중 국가법령정보 공동활용 API에서 현행 원문을 찾지 못하는 항목이 생길 수 있다. 동기화 결과의 실패 목록을 정기적으로 검토한다.

### 운영·검증

- Supabase 마이그레이션은 자동 적용되지 않는다. 새 환경에서는 아래 마이그레이션을 순서대로 실행해야 한다.
- 테스트 자동화는 답변 형식 회귀 스크립트 중심이다. API 통합 테스트, 권한 경계 테스트, 브라우저 WebGPU 테스트 및 업로드 E2E 테스트를 추가해야 한다.
- `.env.example`에는 선택 환경변수 일부가 빠져 있으므로 아래 목록을 기준으로 환경을 구성한다.
- `docs/v2-private-ai-architecture.md`의 초기 “원본 격리 저장” 설명 일부는 현재 구현과 다르다. 현재 구현은 민원 원본 PDF를 저장하지 않고 마스킹 PDF만 저장하며, 이 문서를 최신 기준으로 본다.

## 6. 환경변수

### 필수 Secret

- `SUPABASE_SERVICE_ROLE_KEY`: Supabase 서버 전용 서비스 역할 키
- `OPENAI_API_KEY`: 임베딩, 안내서 Q&A 추출 및 답변 생성에 사용하는 키
- `LAW_OPEN_API_OC`: 국가법령정보 공동활용 API 인증값
- `LEGAL_SYNC_TOKEN`: 보호된 법령 동기화 API 호출 토큰
- `DRAFT_SIGNING_SECRET`: 담당자가 확인한 AI 요청 봉투의 HMAC 서명키. 미설정 시 서비스 역할 키를 대체 사용하지만 별도 키 권장
- `PRIVACY_AUDIT_TOKEN`: 개인정보 재감사 API 보호 토큰

### 필수 일반 환경변수

- `SUPABASE_URL`: `https://<project-ref>.supabase.co`
- `SUPABASE_STORAGE_BUCKET`: 기본값 `complaint-originals`
- `OPENAI_EMBEDDING_MODEL`: 기본값 `text-embedding-3-small`
- `PUBLIC_TEST_MODE`: 운영 `false`, 인증 없는 테스트 사이트만 `true`

### 선택 환경변수

- `OPENAI_DRAFT_MODEL`: 답변 초안 모델. 미설정 시 코드 기본값 사용
- `OPENAI_GUIDE_QNA_MODEL`: 안내서 Q&A 추출 모델. 미설정 시 초안 모델 또는 코드 기본값 사용
- `LEGAL_SYNC_BOOTSTRAP_TOKEN`: 장애 복구 시에만 사용하는 일회용 토큰. 상시 등록하지 않는다.

사이트 환경변수를 변경한 뒤에는 해당 사이트를 다시 배포해야 적용된다. Secret 값은 Git, 문서, 브라우저 또는 로그에 기록하지 않는다.
