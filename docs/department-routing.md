# 전체 부서 소관 분석 로컬 적용 결과

2026-10-12, `codex/search-wide-layout` 브랜치의 로컬 변경입니다. 기존 사용자 변경사항과 Secrets를 보존했으며 커밋·푸시·배포·실제 DB 변경은 수행하지 않았습니다.

## 화면 동작

- 민원 작성 탭의 **문서 불러오기**에서 문서를 읽고 비식별 질의를 준비하면 전체 부서 소관 분석을 자동 실행합니다. kordoc 도우미 및 기존 브라우저 PDF 경로 모두 연결했습니다.
- 초안 작성이나 OpenAI 호출에 성공해야만 소관 분석을 보는 기존 의존성을 제거했습니다. 분석 패널은 질의 입력 바로 아래에 표시합니다.
- 가장 높은 상대 가능성, 전체 비교 가능 부서 순위, 현재 부서 표시, 퍼센트 막대, 입력 질의와 일치한 쟁점, 관련 민원 표본 구간을 보여줍니다.
- 질의를 직접 작성하거나 수정한 경우 **소관 부서 분석**으로 다시 실행합니다. 수정된 질의 또는 변경된 부서에 이전 결과가 섞이지 않도록 요청을 취소하고 결과를 초기화합니다.
- 각 민원 탭이 독립된 결과를 유지합니다. 소관 분석 결과는 서버에 별도로 저장하지 않습니다. 재로그인 후 저장된 질의를 복원하면 분석 버튼으로 다시 비교할 수 있습니다.
- 부서 목록 중 추정치를 제공하지 않은 부서는 펼쳐볼 수 있습니다. 자료 부족이나 약한 일치 신호를 소관 가능성 0%로 오해하지 않도록 구분합니다.

## 비교 범위와 계산

서버는 전체 부서의 `ready` 상태 **민원**을 읽습니다. 기존 5,000개 source 제한과 배치당 1,000개 문서 제한을 제거하고, 실제 반환 페이지 크기로 다음 페이지를 조회합니다. Q&A·법령·안내서는 이 소관 비교의 표본에 포함하지 않습니다. 답변 초안의 근거 검색은 기존 부서 권한 범위를 유지합니다.

민원 제목·분류·질의 요약과 질의 검색 요약의 어휘 일치를 비교합니다. 전체 민원에서 흔하지 않은 질의 어휘에 가중치를 부여하며, 최소 두 어휘의 일치를 요구합니다. 유효 질의 어휘가 하나뿐이면 해당 어휘 일치로 비교합니다. 부서 점수는 가장 유사한 최대 5개 민원 점수의 평균입니다. 민원 수가 많다는 이유만으로 높은 점수를 받지 않도록 합계 대신 평균을 사용합니다.

중복 문서 ID를 제외한 일치 민원이 **3건 이상**인 부서만 순위에 포함합니다. 해당 부서들의 점수를 정규화하고 정수 반올림의 나머지를 배분하여 표시 퍼센트 합계를 100으로 맞춥니다. 상위 5개 부서만 잘라 정규화하지 않습니다.

**퍼센트는 비교 가능한 부서 사이의 검색 점수 비율입니다. 학습·검증된 통계적 확률이나 법적 소관 판정은 아닙니다.** 비교 가능한 부서가 하나인 경우 100%는 그 부서가 확실한 소관이라는 뜻이 아닙니다. 화면에도 비교 부서 수와 상대 추정치라는 설명을 표시합니다. 약한 신호나 소수 표본 때문에 제외된 부서도 실제 소관일 수 있습니다.

## 개인정보와 권한

- 승인된 개인 계정만 전체 부서 분석 API를 호출할 수 있습니다. 공개 테스트 계정은 실제 기관 전체 부서 집계에 접근하지 못합니다.
- 질의는 브라우저에서 비식별한 후 전송하며 서버에서 잔여 개인정보 패턴을 재검사합니다. 원본 파일은 기존 로컬 처리 경계 안에서 유지합니다.
- 다른 부서의 문서 제목·원문·답변·개별 문서 ID·출처는 응답에 넣지 않습니다. 표시할 일치 어휘는 사용자가 제출한 질의에서만 가져옵니다.
- 표본 수는 정확한 숫자 대신 `3~9건`, `10~49건`, `50건 이상` 구간으로 표시합니다.
- 이 비교 결과를 외부 AI에 보내거나 다른 부서 자료를 답변 작성 근거로 승격하지 않습니다.
- API는 `private, no-store`로 응답합니다. 데이터 연결 실패와 충분한 일치 신호가 없는 경우를 구분합니다.

## 검증 및 적용

`test:routing`은 실제 순위 모듈과 API 핸들러를 사용하고 인증/DB 전송 경계만 모킹합니다. 기존 5,000개 source 이후에 있는 부서의 조회, 낮은 서버 페이지 상한, 중복 제외, 3건 미만 집계 차단, 자료 수 편향 방지, 퍼센트 합계, 원문/출처가 없는 집계 응답, 개인 계정 승인/권한, 다른 출처 요청 차단, 데이터 오류 상태를 검증했습니다.

새 소관 분석 테스트와 `test:workspaces`, 개인정보 회귀 242/242, 답변 템플릿 및 문서 처리 회귀 테스트가 통과했습니다. 로컬 프로덕션 빌드도 통과했습니다. 전체 TypeScript 검사에는 기존 오류가 남아 있으며 새 소관 분석 모듈/컴포넌트/API 관련 진단은 없었습니다.

이 기능에는 새 DB 마이그레이션이나 Secret이 필요하지 않습니다. 기존 DB 스키마와 Supabase 서버 설정을 사용합니다. 개인 계정 기능을 테스트하려면 승인된 사용자와 `PUBLIC_TEST_MODE=false` 환경이 필요합니다. 앞서 만든 민원 탭의 계정 저장 기능은 별도의 workspace 마이그레이션 적용이 필요합니다.

실제 테스트 사이트에는 아직 반영하지 않았습니다. 이 환경의 로컬 브라우저 연결 문제로 새 UI의 브라우저 종단 검증을 완료하지 못했습니다. 실제 부서별 자료로 소관 추정 정확도를 평가하지 않았고, 큰 운영 데이터에서 전체 조회의 지연/메모리 사용도 검증하지 않았습니다. 운영 적용 전 테스트 환경에서 문서 업로드 자동 분석, 탭 전환, 재분석, 개인정보 미노출과 알려진 소관 민원에 대한 순위 품질을 확인해야 합니다.

결과 패치와 변경 소스 묶음은 이전 개인정보·kordoc·민원 탭 변경까지 포함하는 누적 로컬 변경입니다. Secrets, 원본 자료, 의존성/모델, 사용자 fixture 삭제/LDH 변경은 제외합니다.
