# 배포 후 점검 목록

테스트 사이트에서 아래 항목을 확인한 뒤 같은 검증 버전을 기본 사이트에 적용한다. 체크 표시는 실제 확인 후에만 한다.

## 배포 직후
- [ ] 테스트·기본 사이트의 배포 커밋을 기록하고 테스트/운영 DB·Storage·Secret 및 PUBLIC_TEST_MODE 설정이 분리되었는지 확인한다.
- [ ] DB 백업과 복구 방법을 확인한 뒤 작성 탭 마이그레이션(202610120001), 서버 전용 권한 마이그레이션(202610130001) 순서로 적용하고 실제 권한을 검증한다.
- [ ] 서로 다른 계정·부서로 자료 조회/수정/삭제, 답변 기록, 최대 10개 탭 저장·다른 PC 로그인 복원·동시 편집 충돌을 확인한다.
- [ ] 공개 테스트는 합성 자료만 사용하고 실제 계정 저장·업로드·기관 전체 소관 집계 접근 차단을 확인한다.
- [ ] 로그아웃 후 세션 갱신 거부, 만료된 로그인, 통신 장애 시 저장 재시도와 복원 상태를 확인한다.
- [ ] 실제 응답의 HTTPS·보안 헤더·캐시 차단과 외부 출처 요청 차단을 확인한다. Storage 비공개 및 원본 접근 정책을 확인한다.
- [ ] 대표 한국어 PDF/HWP/HWPX/Office/스캔 자료로 로컬 도우미 파싱, 표·페이지 보존, 잔여 개인정보와 과잉 마스킹을 담당자가 점검한다.
- [ ] 근거 연결, 법령 현행성, 존댓말·공문서 문체, 근거 부족 시 판단 보류, 소관 추정 표시를 확인한다.
- [ ] 320/375/768/1024/1440px, 200% 확대, 모바일 키보드 및 키보드만으로 탭·모달·작성·검색을 확인한다.

## 운영 시작 시
- [ ] 지속적인 WAF 요청 제한·가입 남용 방지, 관리자 MFA와 이메일 소유 확인 절차를 설정한다.
- [ ] 검색어·민원 본문·토큰을 제외한 장애 알림과 가동률·응답 지연·실패율을 관찰한다.
- [ ] 기존 원본·오류 기록·백업의 보유기간과 삭제 절차를 확정하고 승인된 범위에서 정리한다.
- [ ] 최소 권한 관리자 계정, 접근 기록, 사고 대응 연락체계 및 복구·롤백 절차를 확인한다.
- [ ] 의존성 취약점 점검을 반복하고 개발용 braces 미해결 advisory의 수정 버전을 확인한다.

## 사용성·품질 개선
- [ ] 실제 사용자 평가로 검색 결과 정확도, 부서 소관 순위, 답변 수정량과 작성 시간을 측정한다.
- [ ] 문서별 한국어 OCR 품질과 처리 시간을 측정해 재처리 기준을 정한다.
- [ ] 초기 번들·검색/답변 지연을 측정한 뒤 필요 영역 지연 로딩과 검색 성능을 개선한다.

현재 로컬 회귀와 빌드는 통과했으나 실제 DB 적용·사이트 배포·계정 간 종단 검증·크기별 시각 검증은 완료하지 않았다. GitHub 소스 업로드는 사이트 배포와 별개다.
