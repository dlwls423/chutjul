# kordoc 로컬 MCP 문서 처리

## 처리 경계

사용자 승인에 따라 기존 ‘브라우저 안에서만 원본 처리’를 ‘동일 PC의 로컬 도우미에서 처리’로 확장했다. 원본을 외부 서버나 AI로 보내지 않는다. 사이트는 `127.0.0.1:43127`의 도우미에 선택한 파일 바이트를 전달하고, 도우미는 kordoc 4.21.25 기반 `read_document` MCP 도구로 Markdown·쪽/섹션·제목 경로·표 청크를 반환한다. 브라우저가 마스킹하고 서버가 잔여정보를 검사한 준비 자료만 업로드한다.

이 MCP 도구는 kordoc 라이브러리의 구조화 결과를 반환하는 프로젝트 전용 어댑터다. upstream `parse_document`의 텍스트 응답 길이 제한으로 긴 안내서가 잘리는 일을 피한다. Codex 전역 MCP 설정이나 사용자 Secret은 수정하지 않았다.

도우미는 루프백에만 바인딩하며 Host·Origin·요청별 세션 토큰을 검사한다. 임시 파일은 랜덤 이름으로 작업 디렉토리에 저장하고 처리 완료 후 삭제한다. 비정상 종료의 잔여 디렉토리는 다음 기동 시 제거한다. 파서 stderr는 출력하지 않고 자식 프로세스에 사이트/AI Secret을 전달하지 않는다. 실제 문서 파싱은 `KORDOC_OFFLINE=1`로 수행한다.

## 준비와 실행

Node.js 22.13 이상과 pnpm이 필요하다. 첫 설치에는 패키지 및 OCR 모델 다운로드를 위한 네트워크가 필요하다.

```powershell
cd services/kordoc-local
pnpm install --frozen-lockfile --store-dir .pnpm-store --node-linker=hoisted
node setup-models.mjs
node server.mjs
```

OCR 준비는 도우미가 생성한 합성 이미지로 모델만 내려받는 별도 단계다. 실제 민원은 이 단계에서 사용하지 않는다. 모델은 `.models`에 보관되며 Git에 포함하지 않는다. 폐쇄망 PC는 kordoc의 `models --export`/`--import` 명령으로 사전에 모델을 반입할 수 있다. 인증서 오류가 있는 환경에서는 기관이 신뢰한 인증서 체인을 사용한다. 검증 환경은 Node 24의 `NODE_USE_SYSTEM_CA=1`로 OS 인증서 저장소를 사용했으며 인증서 검증을 끄지 않았다.

기본 허용 사이트는 `http://localhost:3000` 및 `http://127.0.0.1:3000`이다. 테스트 사이트에서 사용하려면 해당 사이트만 명시하여 실행한다.

```powershell
$env:CHUTJUL_ORIGINS='https://chutjul-test.leeyejin113.chatgpt.site'
node server.mjs
```

현재 호스팅된 테스트 사이트에는 이번 코드가 아직 배포되지 않았다. 위 설정만으로 구버전 사이트에 기능이 생기지는 않는다. 브라우저가 로컬 네트워크 연결 권한을 요청하면 사용자가 허용해야 한다.

## 사이트에서 사용

데이터 관리 → 파일 업로드에서 **PC 로컬 도우미 사용**을 켠다. 이 선택은 해당 브라우저에 저장된다.

- 과거 민원은 ‘과거 민원 질의·답변’을 선택한다. 국민신문고 양식을 인식하여 질의·답변을 분리하고, 분리 실패는 저장을 중단한다. 파일명만으로 안내서로 우회하지 않는다.
- 안내서·기타 참고자료는 해당 자료 종류를 선택한다. 전체 비식별 본문과 제목·표·쪽/섹션 구조로 기존 안내서 검색과 답변 근거 경로에 색인한다. 안내서 Q&A 보조 추출 장애가 본문 저장을 중단시키지 않는다.
- 새 민원 분석에서도 문서 불러오기가 로컬 도우미를 사용한다. 양식 없는 문서는 전체 추출 본문을 마스킹해 질문 편집기에 넣고 담당자가 확인한다.
- 도우미를 끄면 기존 브라우저 PDF 처리 경로를 유지한다. 확장 형식을 서버로 직접 전송하는 대체 경로는 없다.

지원 입력: PDF, HWP(3.x/5.x), HWPX, HWPML(.hml), DOCX, PPTX, XLS, XLSX, PNG, JPG/JPEG, WebP. ‘모든 파일’이나 모든 암호·DRM·손상 문서를 읽는다는 보장은 아니다. 도우미는 30MB, 추출 본문은 60만 자로 제한하고 시간 초과·일부 파싱·OCR 실패는 오류로 처리한다. 비치명적 경고 코드는 문서 메타데이터에 남기며 실제 문서의 OCR 정확도는 검수가 필요하다.

## 저장과 검색

- 준비 자료는 비식별 JSON 프로토콜로 전송한다. 서버는 허용 필드·개인정보·자료 종류를 검증하며 부서는 기존 인증 프로필로 제한한다.
- 원본 파일과 준비 자료의 파일 본문을 Storage에 저장하지 않는다. 마스킹된 DB 본문·민원 2트랙·검색 청크·파서 출처 정보만 남긴다. 원본 PDF 미리보기는 제공하지 않으며 기존 PDF 자료의 미리보기는 유지한다.
- 민원 원문 Markdown·페이지·전체 청크는 전송 자료에서 제외한다. 마스킹된 질의·답변과 검색용 요약을 사용한다.
- 참고자료는 kordoc 제목 경로와 표를 청크화한다. 긴 표는 헤더를 반복해 나누고 마지막 행까지 색인한다. 청크에 파서 버전·원본 형식·쪽 기준을 남긴다.
- 실제 레이아웃 쪽만 `page_number`로 색인하며, 섹션/시트/쪽 미확정 자료는 `section_index`를 사용한다. 숫자를 실제 PDF 쪽으로 위장하지 않는다.
- 기존 저장 자료는 자동으로 재처리하지 않는다. 새 구조를 사용하려면 테스트부서에서 원본을 재업로드하고 확인한다.

## 검증

```powershell
pnpm test:documents
pnpm test:privacy
pnpm test:regression
pnpm build
cd services/kordoc-local
node --test test.mjs
```

실제 HTTP→MCP→kordoc 합성 검증: DOCX/HWPX/XLSX/PPTX/텍스트 PDF, PNG/JPG/WebP OCR, 스캔 PDF OCR 총 9개 경로. Origin·토큰·지원 형식 차단, 손상 문서 오류, 임시 파일 삭제도 검사한다. 앱 회귀는 비식별 전송·허용 스키마·타부서 필드 차단·민원 분리·표 분할과 마지막 행 보존·섹션 출처를 검사한다.

HWP3/5·HWPML·XLS의 실제 운영 양식, 한국어 OCR 정확도 평가, 실제 Supabase 색인·검색·AI 답변 종단 검증과 브라우저 로컬 네트워크 연결은 추가 검증이 필요하다. 전체 TypeScript 검사는 기존 응답 `unknown` 타입 및 `.ts` import 설정 오류 등으로 통과하지 않는다. 빌드와 추가 회귀 테스트의 성공을 전체 타입 검사 통과로 해석하지 않는다.
