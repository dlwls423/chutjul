# 첫줄 V2 개인정보 보호형 AI 처리 구조

## 목표

- 원본 PDF와 민원 원문은 신뢰 경계 안에서만 처리한다.
- OpenAI API에는 원문, 개인정보, 민감한 사업정보를 보내지 않는다.
- 답변 품질에 필요한 사실관계와 법적 쟁점만 구조화하여 전송한다.
- 외부 전송 직전과 저장 직전에 별도의 검증을 수행하고 실패 시 전송을 중단한다.

## 권장 처리 흐름

1. **원본 격리 저장**
   - 원본 PDF를 비공개 Storage에 암호화하여 저장한다.
   - 원본 접근은 담당 부서와 관리자에게만 허용한다.
2. **로컬 추출**
   - PDF 텍스트/OCR 처리는 내부 서비스에서 수행한다.
   - 이 단계에는 외부 LLM을 호출하지 않는다.
3. **로컬 개인정보·민감정보 탐지**
   - 정규식·체크섬·사전 규칙과 로컬 NER/LLM을 함께 사용한다.
   - 이름, 연락처, 주민번호뿐 아니라 회사명, 서비스명, 계약금액, 계정, 내부 시스템명도 분류한다.
4. **최소정보 사건 스키마 생성**
   - 로컬 LLM이 민원 원문을 아래 구조로 요약한다.
   - 자유문 원문 대신 허용된 필드만 다음 단계로 넘긴다.
5. **사람 검토**
   - 담당자가 원문과 구조화 결과의 차이를 확인하고 수정한다.
   - 기본값은 `검토 후 AI 초안 생성`으로 한다.
6. **외부 전송 전 DLP 게이트**
   - 구조화 결과를 다시 스캔한다.
   - 금지 유형이나 원문과 긴 동일 구절이 발견되면 OpenAI 호출을 차단한다.
7. **부서 한정 RAG 검색**
   - 구조화된 쟁점으로 현재 사용자의 부서 자료만 검색한다.
   - 과거 민원 원문 대신 승인된 답변 패턴과 공개 법령·안내서 근거를 사용한다.
8. **답변 초안 생성**
   - OpenAI에는 최소정보 스키마, 공개 근거, 작성 규칙만 전달한다.
   - API 요청은 저장 비활성화 옵션을 사용한다.
9. **감사 기록**
   - 외부 전송 내용 자체가 아니라 해시, 필드명, 길이, 탐지 유형, 승인자, 시각을 기록한다.

## 외부 전송 허용 스키마 예시

```json
{
  "department": "범정부마이데이터추진단",
  "intent": "개인정보 전송요구권 제도 적용 여부 질의",
  "facts": [
    "공개 Open API만 사용함",
    "사용자 인증정보를 사용하지 않음",
    "기관 보유 개인정보를 전송받지 않음"
  ],
  "legal_questions": [
    "개인정보 보호법 제35조의2 적용 여부"
  ],
  "requested_output": [
    "적용 여부",
    "추가 준수사항",
    "근거 법령"
  ],
  "uncertainties": [
    "홈페이지 이용약관상 자동 접근 제한 여부 확인 필요"
  ],
  "outbound_safe": true
}
```

## 저장 데이터 구분

- `content_original`: 원문. 비공개·부서 제한·외부 전송 금지.
- `content_masked`: 개인정보 치환본. 내부 조회와 품질검사용.
- `case_summary_private`: 로컬 모델이 만든 상세 요약. 내부 전용.
- `case_facts_outbound`: 허용 목록 스키마. 외부 AI 전송 가능.
- `pii_entities`: 원문 값 없이 유형, 위치, 탐지기, 신뢰도만 저장.
- `outbound_audit`: 전송 해시, 모델, 근거 ID, 승인자, 차단/허용 결과.

## 로컬 LLM 적용 원칙

- 1차 적용 대상은 개인정보 탐지 보조와 사건 스키마 생성이다.
- 정규식 탐지를 대체하지 않고 보완한다.
- 출력은 JSON Schema로 강제하고 스키마 밖 자유문을 허용하지 않는다.
- 로컬 모델이 실패하거나 확신도가 낮으면 외부로 우회하지 않고 사람 검토 상태로 전환한다.
- 최종 답변 생성까지 로컬화할지는 한국어 법률 질의 평가셋 결과로 결정한다.

## 배포 및 승격 정책

- `codex/v2-private-pipeline`: V2 개발 브랜치.
- 테스트 사이트: 구현 및 개인정보 누출 테스트 대상.
- 운영 사이트: 동일 커밋이 테스트를 통과한 뒤에만 승격.
- V1 기준점: Git 태그 `v1.0.0`.

## 출시 차단 기준

- 외부 요청 본문에서 원문 개인정보 1건이라도 검출됨.
- 원문과 외부 전송문 사이에 허용 길이를 넘는 동일 구절이 존재함.
- 질의 핵심 사실 또는 답변 근거가 누락됨.
- 다른 부서의 검색 청크가 포함됨.
- 법령명·조문이 저장된 근거와 일치하지 않음.
