# 첫줄 프로젝트 현황

기준일: 2026-10-24

기준 브랜치: `experiment/browser-ai`

## 서비스와 소스 기준

- 운영: `https://chutjul.leeyejin113.chatgpt.site`
- 테스트: `https://chutjul-test.leeyejin113.chatgpt.site`
- 안정 개발 기준은 `codex/search-wide-layout`이고 브라우저 AI 답변 실험은 `experiment/browser-ai`에서 진행 중이다.
- 테스트 사이트에는 브라우저 AI 실험이 배포되어 있고 운영 사이트에는 아직 반영하지 않았다. Sites 배포와 GitHub 브랜치는 자동 동기화되지 않는다.

## 기술 구조

- UI/API: React 19, Next 16 호환 Vinext, TypeScript, Cloudflare Workers 기반 Sites
- DB/파일: Supabase PostgreSQL, pgvector, 비공개 Storage
- 인증: Supabase Auth와 서버 전용 서비스 역할 키, 관리자 승인 및 부서 범위
- AI: 브라우저 WebLLM 비식별 요약·근거 선별·답변 생성, 서버 형식·근거·개인정보 검증, OpenAI 임베딩 및 안내서 Q&A 추출
- 검색: 부서 범위 키워드 검색, 저장 청크, 법령 조문 검색, 일부 임베딩 저장. 운영 검색은 아직 완전한 하이브리드 랭킹이 아니다.
- 법령: 국가법령정보센터 Open API → 현행/시행예정/연혁 버전 → 조문 단위 저장 → 일일 GitHub Actions 동기화
- 개인정보: 업무 조회용 질의와 검색·AI용 요약 질의의 2트랙, 브라우저 마스킹, 외부 전송 전 서버 재검사, 담당자 수락

## 현재 주요 위험

1. 기준 Git 브랜치와 실제 배포 소스가 갈라져 있어 회귀 위험이 있다.
2. 키워드 하나만 일치하는 자료가 검색 결과에 포함될 수 있고 관련도 설명이 충분하지 않다.
3. 테스트 사이트의 민원 답변 생성은 브라우저 AI로 전환했다. WebGPU·메모리·모델 다운로드 제약과 소형 모델 품질을 평가해야 하며, OpenAI는 임베딩과 안내서 Q&A 추출에 남아 있다.
4. 운영 DB 마이그레이션은 자동 적용되지 않는다.
5. 실제 민원 표본 기반 개인정보 누락·과잉 마스킹 평가는 계속 필요하다.

## 이번 작업 상태

- 신용정보법 법률·시행령은 기존 수집 목록에 있었음을 확인했다.
- 빠져 있던 시행규칙과 신용정보업감독규정을 추가하는 마이그레이션을 작성했다.
- 법령명 별칭, 조문번호, 마이데이터·전송요구·스크래핑 문맥을 구분하는 검색 분석을 추가했다.
- 운영 DB와 배포 사이트에는 아직 적용하지 않았다.

## 2026-10-24 브라우저 AI 실험 상태

- Qwen2.5 1.5B/0.5B WebLLM을 기기 조건에 따라 선택하고 요약·근거 선별·답변 생성에 재사용한다.
- 부서 권한 검색과 근거 후보 준비는 서버가 수행하고, 답변 생성은 브라우저가 수행한다. 서버는 최종 결과의 개인정보·근거·법령·형식을 검증한다.
- 외부 LLM 자동 우회는 없으며 테스트 사이트에서 실제 모델 적재와 초안 생성을 확인했다.
- 브라우저 모델 컨텍스트 제한에 맞춰 근거 최대 4개·약 4,200자, 출력 1,200토큰으로 조정했다.
- 운영 반영 전 고정 평가셋의 정확성·환각·문체·지연시간·WebGPU 호환성 비교가 남아 있다.
