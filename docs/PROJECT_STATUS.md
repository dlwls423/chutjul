- 테스트: `https://chutjul-test.leeyejin113.chatgpt.site`

- 다음 기능 배포 전에 배포 체크아웃의 최신 커밋을 기준 브랜치로 안전하게 통합하고 회귀 검증해야 한다.

## 기술 구조

- UI/API: React 19, Next 16 호환 Vinext, TypeScript, Cloudflare Workers 기반 Sites
- DB/파일: Supabase PostgreSQL, pgvector, 비공개 Storage
- 인증: Supabase Auth와 서버 전용 서비스 역할 키, 관리자 승인 및 부서 범위
- AI: 브라우저 WebLLM 요약 보조, OpenAI Responses API 답변 생성, OpenAI 임베딩 및 안내서 Q&A 추출
- 검색: 부서 범위 키워드 검색, 저장 청크, 법령 조문 검색, 일부 임베딩 저장. 운영 검색은 아직 완전한 하이브리드 랭킹이 아니다.
- 법령: 국가법령정보센터 Open API → 현행/시행예정/연혁 버전 → 조문 단위 저장 → 일일 GitHub Actions 동기화
- 개인정보: 업무 조회용 질의와 검색·AI용 요약 질의의 2트랙, 브라우저 마스킹, 외부 전송 전 서버 재검사, 담당자 수락

## 현재 주요 위험

1. 기준 Git 브랜치와 실제 배포 소스가 갈라져 있어 회귀 위험이 있다.
2. 키워드 하나만 일치하는 자료가 검색 결과에 포함될 수 있고 관련도 설명이 충분하지 않다.
3. OpenAI 의존 기능은 답변·임베딩·안내서 Q&A 추출로 나뉘며 로컬 대체 실험 전 기준 성능 측정이 필요하다.
4. 운영 DB 마이그레이션은 자동 적용되지 않는다.
5. 실제 민원 표본 기반 개인정보 누락·과잉 마스킹 평가는 계속 필요하다.

## 이번 작업 상태

- 신용정보법 법률·시행령은 기존 수집 목록에 있었음을 확인했다.
- 빠져 있던 시행규칙과 신용정보업감독규정을 추가하는 마이그레이션을 작성했다.
- 법령명 별칭, 조문번호, 마이데이터·전송요구·스크래핑 문맥을 구분하는 검색 분석을 추가했다.
- 운영 DB와 배포 사이트에는 아직 적용하지 않았다.
