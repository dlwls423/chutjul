# 개인정보 검토 및 외부 AI 전송 승인 기준 초안

작성일: 2026-10-12. 기관 승인 전 검토용 초안이며 법률 검토·계약 확인 또는 실데이터 사용 승인을 대신하지 않는다.
현재 승인 상태: **미승인**. 합성 데이터 검증부터 수행한다.

## 승인에 필요한 증빙

| 검토 항목 | 완료 기준 | 현재 상태 |
| --- | --- | --- |
| 원본 격리 | 민원 원본 PDF·마스킹 전 텍스트가 브라우저 외부 요청, 서버 로그, Storage에 포함되지 않는 업로드 E2E 증빙 | 미검증 |
| 비식별 품질 | 아래 회귀 테스트 통과, 별도 검수 표본에서 누락·과잉 마스킹 평가 및 기관 수용 기준 승인 | 합성 평가에서 결함 발견 |
| 전송 승인 | 화면에 표시된 요약·방향성과 실제 요청 본문 일치, 편집 시 이전 승인이 무효화됨을 확인 | 버튼 활성화와 생성 흐름만 확인 |
| 권한 경계 | 미승인 사용자·다른 부서·직접 API 접근·문서/Storage URL 접근 통합 테스트 통과 | 미검증 |
| 부서 집계 | 적은 자료로 개별 사례가 추론되지 않도록 최소 문서 수 기준 적용 및 경계 테스트 | 1건 집계 표시 확인 |
| 외부 처리 조건 | 계약·DPA·적용 프로젝트의 ZDR 여부·보유/삭제·재위탁·처리 지역 등에 대한 기관 검토 증빙 | 확인되지 않음 |
| 감사·파기 | 본문과 Secret을 남기지 않는 접근/전송/요약 편집 감사로그, 문서·청크·임베딩·로그·파일·캐시·백업 파기 정책 | 미검증 |
| 담당자 최종 검토 | 근거의 현행성·적용 범위·초안 사실관계 확인 후 담당자가 확정 | 개별 답변마다 필요 |

실데이터 투입과 운영 승격은 담당자가 각 항목의 증빙 위치, 검토자, 검토일, 승인 또는 보류 사유를 기록한 뒤 결정한다. `store: false` 설정만으로 ZDR 적용 완료로 기록하지 않는다. 이 문서에 Secret, 실제 민원 본문, 개인식별정보를 붙여넣지 않는다.

## 합성 개인정보 회귀 검증

```powershell
pnpm test:regression
pnpm test:privacy
pnpm build
```

`test:privacy`는 브라우저 마스킹, 서버 잔여정보 검사, 편집 요약 및 답변 작성자 마스킹의 실제 함수를 실행한다. 기본 형식 17건과 안전 문구 5건으로 100개 검사를 수행하고, 국제형 전화번호 및 안전 문구 3건을 별도로 검사한다. 미해결 결함도 실패 종료 코드로 반환한다.

`pnpm test:privacy:baseline`은 기존 지원 형식과 탐색 결함을 분리해 관찰하는 진단용 명령이다. 종료 코드 0이어도 GAP이 있으면 운영 승인 근거로 사용할 수 없다. 회귀 로그에는 사례 ID와 단계만 출력한다. 테스트는 fetch 요청을 금지하며 DB·Storage·OpenAI Secret을 사용하지 않는다.

평가셋을 추가할 때는 합성 값만 사용하고, 민감 값 제거·탐지 유형·반복 마스킹 안정성·잔여정보·법적 맥락 보존을 함께 검사한다. 이 테스트는 PDF 시각적 마스킹, WebGPU 모델, API 권한, 네트워크 요청 본문 검증을 대신하지 않는다.

## 2026-10-12 재현 결과

- 기존 답변 형식 회귀 통과.
- 합성 기본 검사 100/100 통과.
- `phone-international`: `+82 10` 형식 전화번호가 브라우저 마스킹과 잔여정보 탐지를 모두 통과하는 누락. 수정 후 전화번호 변형 평가 확대 필요.
- `safe-representative-word`: 일반 표현 ‘대표적인’이 직함 인접 성명으로 오탐됨.
- `safe-complainant-rights`: ‘민원인 권리’가 성명으로 오탐됨.
- 테스트 사이트 초안에서 일반 문맥이 `[추가 검토 필요]`로 치환되는 현상 확인. 위 합성 오탐과 동일 원인인지는 추가 확인 필요.
- 다른 부서 소관 가능성에서 관련 자료 1건이 표시됨. 원문은 화면에 표시되지 않았으나 최소 문서 수 억제는 필요.

다음 구현은 위 누락·오탐을 브라우저 텍스트, PDF 마스킹 범위, 서버 검사에 일관되게 수정하고 `test:privacy`를 통과시키는 작업이다. 이후 소수 부서 집계 억제 및 업로드/API 권한 E2E를 추가한다. 실제 데이터 일괄 재처리·삭제는 별도 범위와 복구 방식을 확정한 뒤 수행한다.
