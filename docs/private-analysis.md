# 새 민원 분석 개인정보 경계

원문/PDF/마스킹본은 PrivateAnalysis의 메모리에만 보관한다. PDF는 unpdf로 브라우저에서 읽으며 스캔 OCR을 외부로 위임하지 않는다. 로컬 WebLLM은 고정 항목 ID만 제안한다. 모델 실패 시 원문 기반 서버/외부 요약으로 대체하지 않는다. 사용자는 수동 항목 선택을 할 수 있다.

서버는 정의된 법적 쟁점/업무 사실 ID 이외 값을 거부한다. 원문, 자유로운 요약 문장, 이름, 메타데이터, 파일은 요청에 포함하지 않는다. 지원 항목 외 민원은 담당자의 직접 검토가 필요하다. 고정 항목에도 민원 유형 자체의 정보는 담기므로 외부 전송 전 사용자 승인이 필요하다.

prepare는 현행 표시 및 시행일을 검사한 공개 법령을 검색하고 잔존 개인정보 탐지기를 통과한 본문만 채택한다. 기존 법령 파서의 조문/가지번호 정확성과 동기화 최신성은 별도 검토가 필요하며 UI에서 원문을 확인한다. 과거 민원/답변/안내서 업로드는 외부 근거에서 제외한다.

서버는 전체 OpenAI 요청을 사용자/부서/10분 만료시간에 묶어 HMAC으로 서명한다. generate는 명시적 승인과 서명을 검증하고 확인된 요청 그대로 전송한다. 요청/응답 본문을 로그나 DB에 저장하지 않는다. store:false는 제공자의 모든 보존을 끄는 설정이 아니다. 편집/다운로드는 기기에서만 한다.

검증: node scripts/test-private-draft.mjs. 합성 입력/가짜 공개법령/모의 OpenAI를 이용해 원문필드/알 수 없는 항목/위조 서명/미승인 요청 차단과 전송 미리보기 동일성을 확인한다. 실제 WebGPU 실행 속도/품질과 기관 개인정보 기준에 따른 운영 검증은 별도 필요하다.
